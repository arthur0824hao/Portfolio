# 代謝

工作告一段落後，後來的接手者還需要知道原件去了哪裡。代謝從已封存的資料整理出索引和摘要，保留回查原件的線索。摘要解釋那批資料的用途；清冊則讓人檢查封存時有沒有漏件或損壞。

## 小圖

```text
已封存原件 → 封存清冊 → 逐件核對
                          ├─ 核對相符 → 索引保留原件去向
                          └─ 有差異   → 保留原件，列出待查項
```

## 相接部位

Thread 提供已封存的工作記錄。讀者可以先看代謝產生的摘要，再沿索引找回原件，查核當時的判斷。若兩份說明彼此衝突，仍需負責內容的人裁決。

## 數字與限制

**380 / 380 份封存檔通過完整性核對。** 分母取自該批封存前的清冊。每一份都在目的封存區核對大小與內容摘要，並檢查壓縮檔的完整性。這項結果只涵蓋該批檔案；內容是否正確、是否獲採用，以及節省多少空間，都需要各自的證據。

## 示範輸入 → 輸出

圖樣類的甲與乙都是 `circle`。文字類的丙、丁、戊分別是 `note`、`caption`、`circle`。在本資料夾用 Python 3 執行 `python3 -I -B demo.py`，輸出如下：

```text
{"圖樣": [["甲", "乙"]], "文字": []}
輸入保留筆數 5
```

戊與甲的內容相同，但屬於不同類別，因此沒有進入同一組候選。文字類保留在結果中，空清單表示組內沒有重複。
